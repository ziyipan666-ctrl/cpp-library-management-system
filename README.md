# 图书管理系统（Old Version）

> 大一课程设计版本  
> C++ 控制台图书管理系统

## 项目简介

本项目是大一阶段完成的图书管理系统，实现了基础的图书管理、用户管理以及借阅管理功能。

该版本主要目标是完成课程设计要求，实现一个能够运行的图书管理程序。

由于开发阶段主要关注功能实现，因此代码结构较为简单，采用传统 C++ 多文件方式组织代码。

当前版本已保存至 `old-version` 分支，作为后续系统重构和架构优化的基础版本。

---

# 开发环境

- 编程语言：C++
- 开发工具：Dev-C++
- C++标准：C++11
- 数据存储：TXT文件
- 程序类型：控制台应用

# 系统功能

- 用户名
- 密码

### 用户登录

系统支持基本图书操作：

- 添加图书

图书信息包括：

- 图书编号
- 图书名称
- 作者
- 出版社
- 价格
- 其他基本信息

- 图书归还
- 查看借阅记录

系统通过文件保存借阅信息。

# 4. 管理员功能

管理员具有较高权限：

- 管理图书信息
- 查看系统数据
- 维护图书资源

项目完成了课程设计要求，实现了：

- 用户管理
- 图书管理
- 借阅管理

采用简单结构：

- 类数量较少
- 文件数量较少
- 逻辑集中

- 程序执行流程直观
- 功能调用关系简单

适合作为学习 C++ 基础语法和面向对象思想的练习项目。

# 缺点

随着项目规模扩大，原有结构逐渐暴露出维护问题。

---

## 1. 系统架构不清晰

原项目采用功能划分方式：
main.cpp
|
function.h
|
各功能模块

大量类和函数集中管理，缺少明确的层次划分。


导致：

- 数据层
- 业务层
- 界面层

相互混合。

---

## 2. 代码耦合度较高

部分功能之间存在较强依赖。

例如：

修改图书相关功能时，可能需要同时修改：

- 图书类
- 菜单代码
- 文件操作代码

不利于后期维护。

---

## 3. 单一职责原则不足

部分类承担过多任务：

例如：

一个模块同时负责：

- 用户输入
- 业务处理
- 文件读写

导致代码复用性较差。

---

## 4. 扩展能力有限

如果后期增加：

- 更多用户角色
- 数据库支持
- 图形化界面
- 权限管理

需要修改大量原有代码。

---

## 5. 数据管理方式较简单

使用 TXT 文件：

优点：简单方便

但是：

- 数据安全性较低
- 查询效率有限
- 不适合大量数据

---
